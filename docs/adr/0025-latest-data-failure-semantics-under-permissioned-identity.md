# ADR 0025：权限体系下 latestData 的失败语义与身份隔离

- **Status:** Accepted（设计定稿；实施拆票，本 ADR 不随附代码）
- **Date:** 2026-08-18
- **Scope:** `latestData` 的语义、三类失败的差异化处理、Board 与缓存数据的身份隔离、登出行为
- **Tickets:** 主实施票 [#145](https://github.com/xiaowen-0725/uilab-admin/issues/145)；快照 store 迁移在 [#143](https://github.com/xiaowen-0725/uilab-admin/issues/143)
- **Revision:** 2026-08-18b 按 Codex 对抗评审修订：快照按身份分区（替代单槽身份戳）、新增提交前栅栏（第④闸）、结构元数据泄漏记为已知弱化
- **Spec:** [workbench-board-spec §8.4](../plans/workbench-board-spec.md)（本 ADR 在有 Product Identity 时**部分推翻**该节，公开数据路径不变）
- **Depends on:** [ADR-0024](./0024-widget-data-source-model-and-product-identity-layering.md)（Product Identity / Widget Data Source）

## Context

规格 §8.4 的明文规则是：失败、超时、取消不覆盖上次成功数据，widget 继续显示旧数，错误只落在宿主 chrome 上。为公开数据设计时这是对的——显示昨天的汇率比显示空白诚实。

引入 Product Identity（ADR-0024）后这条规则出现两个漏洞：

1. **权限回收后的残留**：用户被收回 A 车场权限，卡上还挂着 A 场昨天的满位与收入——「继续显示旧数」变成数据泄漏。
2. **换账号后的串数**：Board 在 IDB 里是应用级全局的，账号 B 登录会直接看到账号 A 建的板和板上缓存的 A 的经营数据。

根因是 `latestData` 的语义变了：它不再是「上次成功的快照」，而是「**在某个身份、某个授权下**上次成功的快照」。

## Decision

### 1. 数据快照按身份分区（独立 store，不是单槽加戳）

widget 的成功数据从 `BoardWidgetRecord.latestData` 单槽迁出，改为独立 store（如 `widgetDataSnapshots`），key 为 `(widgetId, principalKey)`——**每个身份有自己的快照槽**。渲染时只读当前身份的槽。这是下面所有规则的结构基础。

单槽 + 身份戳的方案被否决：只要账号 B 刷新成功就覆盖了 A 的快照，实际是 last-writer-wins，「切回即恢复」的承诺在结构上不成立。无身份路径（模板默认、示例板、公开 `job`）使用哨兵 principalKey（如 `'anonymous'`），行为与今天一致。

### 2. 三类失败，三种处理

| 失败原因 | 旧数据 | 理由 |
|---|---|---|
| 网络错误、超时、取消 | **保留**（§8.4 原规则不变） | 数据旧了，但你本来就该看到 |
| 登录失效（token 过期、被踢下线） | **遮蔽**（不删，同一身份重登即恢复） | 此刻无法证明你还是这个人 |
| 权限被回收（资源不在授权集合内，或权限不满足查询声明的 `requiredPermissions`） | **清除**该身份该卡的快照并停止刷新 | 你已经不该看到这些数 |

「登录失效」不得混进普通失败态：值班板上「取数出错（可看旧数）」与「需要重新登录（旧数遮蔽）」后果完全不同，UI 必须分开呈现。

### 3. Board 结构共享，缓存数据按身份隔离

换账号登录时：板与卡的**结构**（关心哪些场的哪些指标）保留——它是有复用价值的长期资产；缓存的经营数据在各自身份的快照槽里互不可见，切回原账号读回自己的槽即恢复（§1 的分区使这个承诺在结构上成立）。不做「Board 按身份复制」也不做「登出删整块板」。

**已知弱化（有意接受的权衡）**：结构本身仍是租户元数据——板名、卡标题、数据来源参数里的资源 ID 会向共享机器上的其他账号暴露「谁在关注哪些场的哪些指标」。接受理由：结构复用价值高于该泄漏面（Q6 决策）。缓解缝：`BoardStorePort` 预留按身份过滤能力，面向多账号共享机器的派生应用可在 identity 适配器层加严为结构全隔离；模板默认不启用。

### 4. 「登出即清空」只指主动登出

- **主动登出**（用户点退出）：删除该身份的**全部快照行**并取消其 in-flight 求值，意图明确——不要在这台机器上留我的经营数据。
- **被动失效**（token 过夜过期、后台踢线）：只遮蔽（快照行不动）。身份与授权都没变，只是暂时无法证明；重登后立刻有昨天的数并开始刷新，而不是早高峰打开一块空板。

### 5. 四道闸：求值前三道 + 提交前栅栏（求值器在渲染层，见 ADR-0024 §4）

```
① 产品身份还有效吗 ——失效→ 标记「需重新登录」，遮蔽相关数据，不混入普通失败
② 参数还在授权范围内、且权限满足查询声明的 requiredPermissions 吗
   ——回收/不满足→ 清除该身份该卡的快照，停止刷新
③ 求值（开始时捕获 principalKey + 身份代际 identityGeneration / 授权 revision）
④ 提交前栅栏：在写快照的同一 IDB 事务里重校验代际，不匹配则丢弃结果
```

第④闸封死 TOCTOU 竞态：作业可运行 60–120 s，若登出或撤权发生在运行中途，清除动作完成后旧请求仍会成功返回——没有栅栏它会把刚清掉的数据写回去。配套动作：登出与撤权**主动取消**相关 in-flight run（栅栏是兜底，取消是缩短窗口）。该栅栏与 ADR-0024 §4 的调度提交检查是**同一机制**（execution key + 代际校验），一次实现两处复用。

无身份实现（模板默认、示例板、公开 `job`）四道闸全部直通，行为与今天完全一致。

## Considered options

- **单槽 `latestData` + 身份戳**（本 ADR 初稿方案）：账号 B 刷新即覆盖 A 的快照，实际是 last-writer-wins，「切回即恢复」结构上不成立；Codex 对抗评审判为 no-ship。改为按身份分区的独立快照 store。
- **只做求值前三道闸、无提交栅栏**（初稿方案）：撤权/登出中途完成的旧请求会把已清除的数据写回。补第④闸。
- **保持 §8.4 一刀切保留旧数**：在权限体系下是数据泄漏。否。
- **一刀切清空（任何失败都清）**：把网络抖动变成空白板，对公开数据是倒退，且违背「空白 widget 是在撒谎」的既有论证。否。
- **被动失效也清空**：每天早上打开都是空板 + 全量重取，恰好毁掉早高峰这个最需要立刻可用的时刻。否。
- **Board 按身份复制隔离**：把可共享的结构资产也复制了，与「看板是长期资产」定位冲突。否。
- **登出策略做成产品可配置项**：曾是 Q7 的建议方向，最终收敛为固定语义（主动清空/被动遮蔽），减少派生应用的策略面；确有需要时派生应用可在身份适配器层加严。

## Consequences

- IDB additive 迁移：新增快照 store（key `(widgetId, principalKey)`），`BoardWidgetRecord.latestData` / `latestDataAt` 迁入哨兵身份的快照行后废弃（迁移期兼容读）。删 widget / 删 Board 级联删其全部快照行。
- 求值链路需要身份代际概念：`IdentityScopePort` 暴露单调递增的 generation / 授权 revision，登出、重登、授权快照变化都递增。
- widget 状态机可能需要一个呈现层的「遮蔽」态；它不是 run 状态（§1.3 四态不动），是渲染前「当前身份的快照槽是否可读」的判定结果。
- 主动登出的快照删除与 in-flight 取消应走一个事务边界；遮蔽是纯读侧判定，零写入。
- 结构元数据（板名、卡标题、资源 ID 参数）对同机其他账号可见是已知弱化（§3）；`BoardStorePort` 留按身份过滤缝，模板默认不启用。
- 规格 §8.4 标题所述规则从此限定于「同一有效身份下的取数失败」；公开数据与示例板路径行为不变。
