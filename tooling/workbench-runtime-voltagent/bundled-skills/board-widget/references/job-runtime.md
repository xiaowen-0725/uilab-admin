# 取数作业写作规范

作业跑在 Deno 子进程里。权限即合同：`--no-remote --cached-only`，网络只放行 `allowedHosts`，不给 `--allow-env`。

## 审批与弱化

`board_job_finish` 会停靠用户审批。审批卡展示作业标题、可访问域名、代码规模，以及「批准后此作业可被重复运行，不再逐次确认」。

**`full-access`（完全访问）预设下这张卡不出现**：该档位对一切返回批准，用户对作业授权无感知。这是用户显式选择的档位，不是缺陷。用户可见的撤销入口在小组件 chrome 的「取数作业」弹窗。

停靠审批不是失败。不要把停靠当成 `board_job_finish` 失败并重试。

## 规范

### J1

单文件、**零依赖**，导出 `run(ctx)`；不得 `import` 任何模块。

违反：`--no-remote --cached-only` 让 import 直接失败，finish 拒收。

### J2

用全局 `fetch`；所有要访问的主机必须在 `allowedHosts` 显式声明。

违反：未声明主机会被 Deno 权限层直接拒。

### J3

只能读写 `ctx.runDir`；碰不到工作区，也碰不到自己的代码。

违反：路径逃逸被静态拒，或运行时写盘失败。

### J4

源码静态上限 **64 KiB**（`finish` 拒）；返回可 JSON 序列化对象，产物**硬顶 512 KiB**（运行时拒）。聚合/裁剪在作业里做，不要原样回传上游响应。

违反：源码超限被 finish 拒；产物超限被运行时拒。

### J5

首版只支持公开端点：不要写死密钥，也读不到环境变量（未给 `--allow-env`）。

违反：`Deno.env` / `Deno.run` 被静态拒；密钥会出现在审批卡上。

### J6

60 s 超时（硬顶 120 s）：不要重试风暴、不要长轮询。

违反：作业被宿主杀掉，chrome 显示超时。无法机器校验。

### J7

**幂等**：审批一次之后可被重复静默执行，作业不得有副作用。

违反：每次刷新都改远端状态，用户无法预知后果。无法机器校验。

## Deno 权限后果

| 你写了 | 结果 |
|---|---|
| `import "https://…"` 或 `import "./x.js"` | finish 拒收；即便漏网，运行时也被 `--cached-only` 打死 |
| `fetch` 未声明的主机 | 权限拒绝 |
| `Deno.env.get(...)` | finish 拒收；运行时也没有 `--allow-env` |
| 写 `/etc`、`/Users`、`..` | finish 拒收 |
| 返回超过 512 KiB | 运行失败，旧数据继续显示 |
